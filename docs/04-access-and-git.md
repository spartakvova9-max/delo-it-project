# ИСР, ветки и права репозитория

## Разделение понятий

ИСР декомпозирует объём проекта на результаты и пакеты работ.
Ветки Git сохраняют версии этих результатов, но не заменяют ИСР,
расписание и механизм авторизации. Создание ветки само по себе никому
не предоставляет и не ограничивает доступ.

## Соглашение по веткам

- `main` — интегрированные проверенные результаты этапов;
- `lifecycle/01-initiation` — устав и начальная структура;
- `lifecycle/02-analysis` — требования и приёмка;
- `lifecycle/03-design` — модель, ИСР, матрицы прав;
- `lifecycle/04-implementation` — исходный прототип;
- `lifecycle/05-testing` — тесты и исправления;
- `lifecycle/06-deployment` — запуск и передача.

Этап создаётся от актуальной `main`, результат фиксируется коммитом,
затем сливается через `git merge --no-ff`. Ветки этапов сохраняются для проверки.
Для незавершённого изменения применяется `git stash push -u`, восстановление —
`git stash pop`; stash не заменяет опубликованный коммит и не является резервной копией.

## Проектные категории пользователей

| Категория | Результаты ИСР | Предусмотренное взаимодействие с GitHub |
|---|---|---|
| Владелец / руководитель | 1.*, 6.* и приёмка всех этапов | Создаёт репозиторий, меняет настройки, интегрирует результаты |
| Аналитик | 2.* | Читает Public, предлагает изменения требований через fork/PR |
| Проектировщик | 3.* | Предлагает изменения модели и API через fork/PR |
| Разработчик | 4.* | Предлагает код через fork/PR; при приглашении collaborator может push |
| Тестировщик | 5.* | Читает, запускает тесты, предлагает тесты/дефекты через fork/PR |
| Преподаватель / наблюдатель | Все результаты | Анонимное чтение и clone, без push и настроек |

Это организационная матрица индивидуального учебного проекта, а не заявление
о наличии шести разных GitHub-аккаунтов. Фактически используется один владелец;
дополнительные участники, аккаунты ассистентов и боты не приглашаются.
Публичный читатель не получает право изменять исходный репозиторий.

## Технические ограничения GitHub

У личного репозитория есть владелец и collaborators; детальные роли
Read/Triage/Write/Maintain/Admin относятся к репозиториям организаций.
Нельзя выдавать простое именование lifecycle/* за назначение таких прав.
Правило защиты `main`, если настроено и проверено через GitHub API,
должно отдельно фиксироваться в протоколе: запрет force-push/удаления,
обязательные успешные проверки. Настройка CI-файла сама по себе
ещё не означает, что проверка фактически выполнена или обязательна.

В публичный репозиторий не включаются университетские файлы, отчёт,
реальные документы, пароли, токены, файлы БД и служебные скриншоты.
Настройки пользователя Git используют публичный адрес users.noreply.github.com.
