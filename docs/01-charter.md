# Устав проекта

## Основание и назначение

Вариант К–Л задания по дисциплине «Проектная деятельность в ИТ»:
разработка информационной системы «Делопроизводство» и организация
её жизненного цикла в публичном репозитории GitHub.
Объект автоматизации — условная канцелярия небольшой организации.
Раздельные таблицы и переписка затрудняют поиск документов, контроль срока
и восстановление истории действий. Назначение прототипа — единый журнал
регистрации, маршрутизации и исполнения без хранения оригиналов файлов.

## Цель и измеримые результаты

1. Регистрировать документ с уникальным номером вида `ВХ-2026-0001`.
2. Проводить документ по маршруту «Зарегистрирован → В работе → Исполнен → Архив».
3. Не разрешать недопустимые действия и потерю обновления карточки.
4. Искать кириллические наименования, выбирать период и просроченные документы.
5. Воспроизводить установку и тесты из чистого клона.
6. Подтверждать этапы, команды Git и обмен с удалённым репозиторием реальной историей.

## Границы

Включено: карточка без вложений, справочник четырёх учебных ролей,
автонумерация, назначение, контроль сроков, журнал, выгрузка CSV.
Не включено: юридически значимая электронная подпись, сканирование,
реальные учётные записи и SSO, разграничение секретности документов,
вложения, интеграция с почтой и электронным архивом организации.
Это исполняемый учебный прототип, не готовая промышленная СЭД.

## Жизненный цикл и контрольные точки

Выбрана последовательная учебная модель с возвратом к анализу при дефекте:
инициация → анализ → проектирование → реализация → тестирование → передача.
Переход разрешается после проверки результата этапа, а не просто после создания ветки.
Если дефект обнаружен на проверке, вносится отдельный исправляющий коммит,
затем повторяются тесты. История не переписывается.
Плановая оценка ИСР — 64 человеко-часа; это оценка трудоёмкости, не заявление
о фактически потраченном времени и не календарный срок выполнения.

## Риски и меры

| Риск | Вероятность / влияние | Мера | Критерий контроля |
|---|---|---|---|
| Ошибка прав | Средняя / высокое | Проверка роли в сервисе, не только скрытие кнопки | Отказы 403 и неизменность данных |
| Дубликат номера при параллельной записи | Средняя / высокое | BEGIN IMMEDIATE, UNIQUE | Конкурентный тест |
| Потерянное обновление | Средняя / среднее | Поле version, отказ 409 | Тест двух редакторов |
| Утечка реальных документов | Низкая / высокое | Только синтетические фикстуры, нет загрузки файлов | Проверка дерева и истории Git |
| Потеря локальной копии | Средняя / высокое | Публикация коммитов и проверка свежего клона | Совпадение HEAD, повтор тестов |
| Недоступность GitHub | Средняя / среднее | Локальные коммиты, повтор сетевых операций | Не выдавать локальную копию за удалённую |

## Проектные категории участников

Руководитель принимает границы и выпуск; аналитик описывает сценарии;
разработчик реализует; тестировщик проверяет; преподаватель читает результаты.
В индивидуальном учебном проекте эти рабочие роли совмещаются одним владельцем.
Реальных дополнительных участников не предполагается.
