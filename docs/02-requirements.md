# Требования и критерии приёмки

## Предметная область

Документ имеет вид (входящий, исходящий, внутренний), тему, корреспондента,
дату регистрации, срок исполнения, ответственного и состояние.
Регистрационный номер неизменяем и уникален в пределах всей базы;
счётчик отдельный для вида и календарного года.
Четыре прикладные роли не являются правами доступа к GitHub.

## Функциональные требования

| ID | Требование | Проверяемый критерий |
|---|---|---|
| FR-01 | Регистрация | Регистратор создаёт документ, получает номер и запись журнала |
| FR-02 | Проверка полей | Пустая тема, неизвестный вид и срок раньше регистрации отклоняются без записи |
| FR-03 | Маршрут | Руководитель назначает только действующего исполнителя; состояние меняется на «В работе» |
| FR-04 | Исполнение | Только назначенный исполнитель завершает свой документ; результат обязателен |
| FR-05 | Архив | Только руководитель архивирует исполненный документ; архив не редактируется |
| FR-06 | Поиск и фильтры | Кириллица ищется без учёта регистра; вид, состояние, период и просрочка комбинируются |
| FR-07 | Контроль сроков | Просрочен незавершённый документ со сроком строго раньше контрольной даты |
| FR-08 | Журнал | Каждая успешная мутация добавляет событие; неуспешная не оставляет следов |
| FR-09 | Выгрузка | CSV соответствует текущему отбору, имеет UTF-8 BOM и защиту от формул |
| FR-10 | Защита от перезаписи | Несовпадение version отклоняется кодом 409; предыдущее значение сохраняется |

## Нефункциональные требования

| ID | Требование | Способ проверки |
|---|---|---|
| NFR-01 | Нет сторонних библиотек времени выполнения | Запуск Python 3.11+ из свежего клона |
| NFR-02 | Согласованная запись | SQLite, внешние ключи, транзакция документа/события/счётчика |
| NFR-03 | Воспроизводимые тесты | unittest с временными отдельными БД, без сети GitHub |
| NFR-04 | Нет реальных персональных данных | Только пять явно учебных пользователей и синтетические документы |
| NFR-05 | Безопасная обработка ввода | Параметризованный SQL, textContent в интерфейсе, предел тела запроса |
| NFR-06 | Ясная граница прототипа | Предупреждение об отсутствии аутентификации и запрет реальных данных |

## Сценарии

UC-01: регистратор заполняет карточку → сервис проверяет поля → назначает номер
→ сохраняет документ и событие одной транзакцией.

UC-02: руководитель открывает зарегистрированный документ → выбирает исполнителя
→ сервис проверяет роль и версию → состояние «В работе».

UC-03: назначенный исполнитель вводит непустой результат → состояние «Исполнен»
→ руководитель переводит документ в архив.

UC-04: аудитор выбирает период и контрольную дату → читает список и журнал,
экспортирует тот же отбор; любая попытка изменения запрещена.

## Состояния и запрещённые переходы

`registered → in_progress → completed → archived`.
Назначение другого исполнителя допускается в `in_progress` и записывается в журнал.
Регистратор может исправлять тему, корреспондента и срок только в `registered`.
Прямые переходы `registered → archived`, `registered → completed`, возврат из
архива и удаление карточек в прототипе отсутствуют.
Повторное исполнение/архивирование отклоняется, а не создаёт повторное событие.

## Приёмка

Все автоматические тесты должны пройти из свежего клона.
Ручная браузерная проверка проходит полный маршрут, отказы прав,
устаревшую версию, кириллический поиск, границы срока и отбор CSV.
Публикация принимается только после анонимного чтения Public-репозитория,
совпадения коммитов и реальных push/clone/fetch/pull.
