# Проектирование

## Архитектура

Браузер → HTTP/JSON (`delo.server`) → предметный сервис (`delo.model`) → SQLite.
Интерфейс не обращается к БД напрямую. Разрешения, допустимость перехода и
оптимистическая блокировка проверяются сервисом, даже если клиент обходит UI.
Один HTTP-запрос использует отдельное соединение SQLite, запись выполняется
через `BEGIN IMMEDIATE`, поэтому счётчик и карточка согласованы.

## Сущности

| Таблица | Ключ / значимые поля | Связи и инварианты |
|---|---|---|
| users | id, display_name, role, active | Роль из registrar/manager/executor/auditor |
| documents | id, number UNIQUE, kind, title, correspondent, registered_on, due_on, assignee_id, status, version, result | assignee_id → users; версия растёт при изменении |
| counters | kind + year, value | Составной первичный ключ; число увеличивается в транзакции регистрации |
| events | id, document_id, actor_id, action, details, created_at | document_id → documents; actor_id → users; только добавление через сервис |

Корреспондент — текстовый реквизит учебной карточки, а не отдельный справочник.
Вложения не сохраняются. Срок и дата регистрации хранятся как ISO `YYYY-MM-DD`.
Времена журнала хранятся в UTC. Номер формируется по виду, году регистрации
и четырёхзначному счётчику; после 9999 длина естественно увеличивается.

## Контракты API

`X-Demo-User` — идентификатор выбранного учебного пользователя.
Он намеренно НЕ является средством аутентификации; пользователи доступны через
`GET /api/meta`. Любой посетитель демонстрации может выбрать любую учебную роль.
Сервис проверяет ролевую модель, но не личность человека. Реальные документы запрещены.

| Метод и путь | Действие / роль |
|---|---|
| GET /api/health | Проверка готовности, без карточек |
| GET /api/meta | Учебные пользователи, справочники состояний |
| GET /api/documents | Список и сводка; любой действующий учебный пользователь |
| GET /api/documents/ID | Карточка и журнал |
| GET /api/export.csv | Экспорт того же отбора |
| POST /api/documents | Создание; registrar |
| PATCH /api/documents/ID | Исправление зарегистрированного; registrar; version |
| POST /api/documents/ID/assign | Назначение; manager; version, assignee_id |
| POST /api/documents/ID/complete | Исполнение; назначенный executor; version, result |
| POST /api/documents/ID/archive | Архивирование; manager; version |

Параметры отбора: `q`, `kind`, `status`, `from`, `to`, `overdue=1`, `as_of`.
Период включает обе даты. Срок равный `as_of` не просрочен.
Сводка рассчитана именно для выбранного набора, а не для всех записей.
JSON-ошибки имеют поле `error`; коды 400 — ввод, 403 — запрет,
404 — отсутствие ресурса, 409 — конфликт состояния/версии, 413 — размер,
415 — неверный Content-Type. Трассировки клиенту не возвращаются.

## Матрица прикладных прав

| Действие | Регистратор | Руководитель | Исполнитель | Аудитор |
|---|---|---|---|---|
| Чтение, поиск, журнал, CSV | Да | Да | Да | Да |
| Создание и исправление registered | Да | Нет | Нет | Нет |
| Назначение / переназначение | Нет | Да | Нет | Нет |
| Исполнение | Нет | Нет | Только своего in_progress | Нет |
| Архивирование completed | Нет | Да | Нет | Нет |
| Удаление | Нет | Нет | Нет | Нет |

## Решения по интерфейсу

Единый реестр со строкой поиска, фильтрами, четырьмя счётчиками и карточкой справа.
Окно регистрации содержит подписи полей и нативную валидацию, но сервер
всегда повторяет проверку. Пользовательский текст выводится через `textContent`.
Ошибка не закрывает карточку, кнопки блокируются на время запроса.
Просрочка отмечается текстом и цветом, поэтому не зависит только от восприятия цвета.
