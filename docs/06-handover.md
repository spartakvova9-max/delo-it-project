# Запуск, демонстрация и передача

## Воспроизведение

Нужен Python 3.11+ со стандартным модулем sqlite3. Сторонние пакеты не нужны.
Из корня репозитория:

```sh
python --version
python -m unittest discover -s tests -v
python -m delo --demo --host 127.0.0.1 --port 8080 --db data/demo.sqlite3
```

Открыть `http://127.0.0.1:8080`. На сервере предварительного просмотра
допускается `--host 0.0.0.0`; интерфейс использует только относительные URL.
Запуск с `--demo` обязателен. Первый запуск создаёт пять учебных пользователей
четырёх ролей и шесть карточек; повторный запуск заполненную БД не стирает.
Для чистой демонстрации укажите другой путь `--db`; не удаляйте нужную БД.

## Данные и маршрут

Контрольная дата в интерфейсе — явно выбранное значение 18.11.2026, не системные часы.
При неизменённых фикстурах: 6 документов, 4 активных, 2 просроченных,
1 исполненный, 1 архивный. Срок 18.11.2026 на эту же дату ещё не просрочен.

1. Выбрать регистратора; создать входящий документ с корректными датами.
2. До назначения можно исправить тему, корреспондента и срок.
3. Выбрать руководителя; открыть карточку и назначить исполнителя А.
4. Выбрать исполнителя А; ввести результат и завершить исполнение.
5. Выбрать руководителя; передать исполненный документ в архив.
6. Выбрать аудитора; проверить четыре события или пять, если была правка.
7. Найти карточку по кириллической теме, отфильтровать период, скачать CSV.

Исполнитель Б не может завершить поручение исполнителя А.
Аудитор не создаёт и не изменяет карточки. Старый номер version возвращает 409;
нужно обновить карточку и повторить действие осознанно.

## Модель работы с Git

`git status` показывает рабочее дерево и индекс, `git add` сохраняет выбранное
содержимое в индексе, `git commit` фиксирует снимок. У каждого этапа своя ветка.
`git fetch origin` обновляет ссылки origin/* без слияния рабочей ветки.
`git pull --ff-only` выполняет fetch и допускает только линейное продвижение
текущей ветки; при расхождении останавливается вместо неявного merge.

В репозитории сохраняются исходные ветки этапов и merge-коммиты.
Удалённый сервер не заменяет резервное копирование незакоммиченных изменений.
Локальная БД, ключи и токены исключены .gitignore, но это не защита уже
попавших в историю секретов: перед публикацией проверяется вся история.

## Передача

Перед выпуском необходимо подтвердить автоматические тесты, браузерную приёмку,
целостность Git и повтор тестов из отдельного чистого клона.
В проекте не используется GitHub Actions: автоматические тесты воспроизводятся
локально, в том числе в независимом клоне. Статус local-tests в GitHub, если
установлен после проверки, обозначает локальный запуск, а не облачный CI.
Нельзя выдавать план прав за фактически настроенную защиту: результаты
фиксируются отдельным протоколом.
Ограничения внедрения перечислены в SECURITY.md. Данные демонстрационные.
