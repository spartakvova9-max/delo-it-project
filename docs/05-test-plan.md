# План проверки

## Автоматическая проверка

Из корня: `python -m unittest discover -s tests -v`.
Тесты используют временные отдельные базы и не обращаются к GitHub.
Результат определяется фактическим выходом unittest, а не данным текстом.

- Модель: регистрация, независимые счётчики года/вида, поля и даты,
  все прикладные права, состояния и повторные действия, чужой исполнитель,
  версия, кириллический поиск, период, строгая граница просрочки, CSV.
- Транзакции: искусственный отказ вставки события откатывает карточку и счётчик.
- Параллельность: 24 регистрации с восемью потоками без пропусков и дубликатов;
  два редактора версии 1 — ровно один успех и один конфликт 409.
- HTTP: реальные запросы к временному серверу, JSON/Content-Type/размер,
  неизвестные маршруты, защита исходников и БД от выдачи, разрешённый preview host,
  запрет межсайтовой записи, полный маршрут и фильтрованная загрузка CSV.

## Браузерная приёмка

1. Исходные фикстуры: на 18.11.2026 всего 6, активных 4, просроченных 2,
   исполненных 1, архивных 1. Срок равный контрольной дате не просрочен.
2. Регистрация → исправление реквизитов → назначение → исполнение → архив.
3. Прямая запись в API от аудитора запрещена, база и журнал не меняются.
4. Выбор второго исполнителя не позволяет завершить чужое поручение.
5. Повтор сохранения старой версии показывает ошибку без потери первой правки.
6. Кириллический поиск и сочетания фильтров; пустой отбор, сброс.
7. Ошибочный период очищает прежний результат и показывает ошибку.
8. CSV содержит только текущий отбор; формулы экранированы.
9. Пользовательский HTML виден текстом, не создаёт элементов/сценариев.
10. На узком экране диалоги и управление доступны, таблица прокручивается.

## Проверка Git

Реальные init/config/status/add/commit, отдельная ветка и stash push/pop,
история `log --graph --oneline --all`, типы объектов commit/tree/blob.
Публикация через push, независимый clone, отдельное изменение в клоне,
push из него, fetch без изменения рабочей ветки и pull --ff-only.
Все жизненные ветки должны существовать на удалённом сервере,
`git fsck --full` не должен показывать повреждений.
Из свежего анонимного клона повторяются все тесты. Публичность проверяется
без токена. Наличие CI-файла и фактический зелёный запуск — разные проверки.
