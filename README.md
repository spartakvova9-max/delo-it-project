# ИС «Делопроизводство»

Учебный проект: регистрация входящих, исходящих и внутренних документов,
назначение ответственного, контроль сроков, исполнение, архив и журнал событий.
Цель проекта — прослеживаемый жизненный цикл разработки с помощью Git.
Все организации, сотрудники и документы в демонстрационных данных вымышлены.

## Что входит в проект

- Python 3.11+ и SQLite; без сторонних библиотек времени выполнения;
- веб-интерфейс на русском языке, поиск, фильтры и CSV;
- явная учебная модель ролей: регистратор, руководитель, исполнитель, аудитор;
- оптимистическая блокировка и транзакционная нумерация;
- документация этапов, ИСР и воспроизводимые автоматические тесты.

Демонстрационный выбор пользователя не является аутентификацией.
Приложение нельзя использовать для реальных персональных, коммерческих или
служебных документов. Нужные для промышленного внедрения меры перечислены
в документации по безопасности.

## Структура жизненного цикла

| Этап | Ветка | Результат |
|---|---|---|
| 1. Инициация | `lifecycle/01-initiation` | Устав, границы, риски |
| 2. Анализ | `lifecycle/02-analysis` | Требования и критерии приёмки |
| 3. Проектирование | `lifecycle/03-design` | Модель данных, API, ИСР, права |
| 4. Реализация | `lifecycle/04-implementation` | Работающий прототип |
| 5. Проверка | `lifecycle/05-testing` | Модульные и HTTP-тесты |
| 6. Развёртывание | `lifecycle/06-deployment` | Инструкция запуска и приёмки |

Каждый этап создаёт содержательный коммит; в `main` результаты интегрируются
отдельными merge-коммитами. ИСР — дерево результатов работ, а ветки Git —
техническое средство их версионирования; это разные понятия.

## Быстрый запуск

```sh
python --version
python -m unittest discover -s tests -v
python -m delo --demo --host 127.0.0.1 --port 8080 --db data/demo.sqlite3
```

Открыть `http://127.0.0.1:8080`. Флаг `--demo` обязателен.
Первый запуск создаёт 5 учебных пользователей четырёх ролей и 6 карточек;
повторный запуск не стирает БД. Для новой демонстрации задайте другой путь `--db`.
В среде удалённого предварительного просмотра используйте `--host 0.0.0.0`;
все запросы браузера используют относительные адреса.

## Проверка

`unittest` проверяет ролевые правила, переходы, даты, поиск, CSV, транзакционный
откат, параллельные номера и конфликт версий. HTTP-тесты поднимают отдельный
временный сервер. Для запуска тестов не нужны сеть, токены и GitHub.
GitHub Actions в проекте не используется. Статус `local-tests`, если показан
в GitHub, обозначает локальную проверку коммита, а не облачный CI.
Повтор тестов из чистого клона не требует доступа к аккаунту GitHub.
